# Регулярное локальное сохранение через Codex hooks

Для проекта без подтверждённого origin читать [local-directory.md](local-directory.md): явная локальная привязка UUID/пути и вызовы агента. Не выдумывать origin и не включать hooks. У существующих Git-привязок проверка origin сохраняется.

Используются штатные command hooks `UserPromptSubmit` и `Stop`. Первый передаёт текст запроса, второй — `last_assistant_message`; запись выполняется по этим событиям. Таймер, новый daemon, чтение transcript и backfill не нужны. Проверки полноты нет; обязательный inventory не нужен.

Наличие hooks.json не означает запуск: каждый non-managed hook нужно проверить и разрешить в `/hooks`. Новое или изменённое определение пропускается до доверия. Не обходите этот механизм и не подделывайте trust.

## Зарегистрировать проект

Укажите точный корень Git checkout и проверьте origin. Каждый checkout/worktree регистрируется отдельно. Вложенный незарегистрированный Git-проект пропускается; общие рабочие папки и личные чаты по умолчанию не сохраняются.

Выберите приватное хранилище **вне любого Git checkout**, например `~/.codex/macaroni-memory/projects/PROJECT`. У него нет Git и remote. Поле Protocol v1 `repository` указывает исходный проект; `storage_branch: local` означает расширение для локального хранения. Это не опубликованная ветка `macaroni`. Разрешение на код/документацию не разрешает перенос новых сообщений в remote.

Подставьте реальные проверенные значения:

```bash
python3 /path/to/skill/scripts/regular_capture.py \
  --config /absolute/private/capture.json \
  --register-project /absolute/project-checkout \
  --repository https://github.com/OWNER/PROJECT \
  --store-root /absolute/private/projects/PROJECT
```

Регистрация пишет только локальный allowlist. Отличающийся прежний mapping блокируется: сначала сравните его. Неизвестные поля config сохраняются. Config должен иметь права `0600`, хранилище — `0700`, файлы — `0600`. Checkout одного проверенного репозитория могут использовать одно и то же хранилище. Разные репозитории не могут его разделять; вложенные/пересекающиеся destinations, symlink, URL с credentials, хранилище внутри Git и изменившийся origin отвергаются. Не регистрируйте широкие папки и неизвестные проекты.

## Настроить hooks и разрешить запуск

```bash
python3 /path/to/skill/scripts/regular_capture.py \
  --config /absolute/private/capture.json --hooks-template
```

Команда выводит точный hooks.json для двух событий, не устанавливает его и не меняет trust. Сохраните существующие hooks; добавьте handlers после сравнения. Предпочтительный путь для одного проекта — `<project>/.codex/hooks.json`. Глобальный `~/.codex/hooks.json` получает события всех локальных сессий до фильтра allowlist; такой scope требует отдельного явного разрешения. Существующий `notify` и остальные настройки сохраняйте.

До включения постоянного capture покажите пользователю определения hooks, корни проектов, destinations, события и фильтрацию. Для записи вне workspace используйте штатное разрешение файловой системы. В поддерживаемой локальной сессии откройте `/hooks`, проверьте definitions и разрешите их через UI. Проектный слой config также требует доверия проекту. Если текущий runtime уже загрузил настройки, начните новую локальную сессию. Установленный skill не доказывает, что hooks уже работают.

Дополните применимый `AGENTS.md` проекта, сохранив существующие инструкции:

```markdown
Память проекта использует macaroni-memory. Опубликованная история — в ветке macaroni
этого репозитория. Новые локальные сообщения — в <PRIVATE_STORE>; перед релевантной
работой прочитай его AGENTS.md и .macaroni/protocol.json. JSON сообщений — первоисточник,
индексы необязательны. Hooks сохраняют полученный UserPromptSubmit/Stop после redaction
без проверки полноты. Не читай приватную историю runtime и не публикуй локальную
переписку по разрешению на код/документацию.
```

В приватном хранилище нужен корневой `AGENTS.md` на основе `assets/AGENTS.memory.md`, адаптированный к local. В опубликованной ветке памяти также сохраняйте корневую инструкцию. Не вливайте ветку памяти в продуктовую ради указателя.

## Гарантии и ограничения

- Обрабатываются только текстовые поля `prompt` и `last_assistant_message`. Пути `transcript_path`/`agent_transcript_path` не открываются; system, reasoning, tool и остальные поля не копируются. Другие события, явные subagent events и известные внутренние delegation wrappers пропускаются.
- Hook даёт session/turn ID, но не provider message ID. Локальный ID строится из session, turn, события и **редактированного** текста. Повтор события — запись нуля файлов; одинаковый текст разных turns остаётся разными сообщениями. Два одинаковых запроса внутри одного turn неотличимы от retry. Для prompt, созданного другим hook, нет отдельного доказательства авторства человека. Не объявляйте эти IDs исходными provider IDs или полной историей.
- Порядок — порядок локального наблюдения, исходное время — `null`. Progress/commentary, прежняя история, вложения и сообщения вне этих событий автоматически не собираются. Независимо доступные разрешённые фрагменты можно сохранить ручным workflow.
- До записи в памяти удаляются распознанные tokens, Bearer, credential assignments, private key blocks, credentials в URL и email. Незавершённый private key блокирует capture. Паттерны не распознают любую чувствительную информацию: включайте сохранение только для разрешённых проектных обсуждений, проверяйте данные перед экспортом и редактируйте чувствительные факты вручную. Исходный payload не пишется в файл или лог.
- Отсутствие inventory, gaps или аудита истории не блокирует запись. Manifests проверяют JSON/хеши/ссылки переданных сообщений. Если пользователь просит проверить фактическое сохранение, используйте [проверяемый flush](flush.md) для доступного user/assistant-фрагмента; недоступную историю укажите отдельно. Прежние необязательные completeness/gaps поддерживаются для совместимости.
- Helper обеспечивает containment, dedup, сохранение неизвестных полей, приватный staging, append-only, locks и откат пойманных ошибок. Занятый lock или неверное состояние пропускают capture с общим предупреждением, не останавливая работу пользователя. Durable queue, автоматического replay и гарантии доставки после crash нет. Lock нельзя удалять вслепую.
- Capture не коммитит, не пушит, не загружает данные в сеть, не расширяет runtime permissions и не читает историю сессий. Отключить режим можно через `/hooks`; удаление проекта из allowlist также останавливает его capture.

Штатный контракт: [OpenAI hooks documentation](https://learn.chatgpt.com/docs/hooks).
