# Как Контрибьютить

Macaroni Messenger в первую очередь остаётся одним HTML-файлом.

На текущем этапе вклад в проект - это не только код.

Если честно, код сейчас может быть даже не самым полезным вкладом.

JavaScript уже достаточно, чтобы браузер на секунду задумался о смысле жизни.

Зато очень помогают:

- документация;
- примеры;
- более честные предупреждения;
- хорошие шутки, которые объясняют архитектуру;
- саркастичные формулировки, которые всё ещё несут смысл;
- маленькие правки, после которых проект легче понять.

Репозиторий не обязан становиться новой Encyclopedia Dramatica.

Но полезную часть можно брать: контрибьютор может добавить стиль, язвительность и насмешку, если после этого читателю понятнее, что происходит.

Перед pull request спросите себя:

- Это может остаться внутри `messenger.html`?
- Это может работать без backend?
- Это может использовать Git как source of truth?
- Это может обойтись без новой dependency?
- Это можно понять ночью без схемы?

Предпочтительные изменения:

- маленькие UI fixes;
- protocol-compatible улучшения `.macaroni`;
- hardening provider adapters;
- repair tools для browser storage;
- честная документация;
- документация, которая смешная потому что точная;
- скучные временные проверки, которые ловят реальные поломки и не обязаны жить в repo вечно.

Особенно welcome:

- синхронные русская и английская документация;
- более короткие объяснения уже принятых решений;
- более острые формулировки скучных ограничений;
- реальные примеры странного поведения git-хостингов;
- заметки, которые объясняют, почему это смешно, но не превращают repo в стендап.

Избегайте:

- серверов;
- build pipelines без крайней необходимости;
- framework migrations;
- realtime infrastructure;
- enterprise abstractions;
- dependencies для задач, которые помещаются в маленькую функцию;
- нового кода только потому, что писать prose оказалось слишком честно.

Шутка продукта не является оправданием сломанного software.

Реализация должна оставаться читаемой, поставляемой и дешёвой в поддержке.

Если фича требует инфраструктуру уровня маленького банка, скорее всего, ей здесь не место.

Если задачу можно решить HTML, JSON и Git, начинайте с этого.

Если задачу можно решить более точной документацией уже существующей странности, начинайте с этого ещё раньше.
