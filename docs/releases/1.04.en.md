# Macaroni Messenger 1.04

Date: 2026-06-15

Release type: hygiene patch, officially nothing alarming again.

Main idea:

Small fixes around settings, branches, and read-only mode.

## What Changed

- Added one more Settings field.
- Called it `Storage branch`.
- Made the default `macaroni`.
- Clarified that the branch is called `macaroni`, while the directory is still `.macaroni/`.
- Did not call the branch `.macaroni`, because Git looks at that like an adult looks at a child's rocket drawing.
- Split source branch and storage branch.
- Source branch remains for `messenger.html`, docs, release notes, and other normal files.
- Storage branch can now receive messages, inbox, receipts, and chat metadata.
- New profiles no longer put chat data into `main` by default.
- Old profiles without `storageBranch` keep using the old branch, so existing chats do not disappear after update.
- GitHub adapter can create the storage branch from the source branch if it does not exist yet.
- GitLab adapter can do the same in its own way.
- GitVerse, Gitea, and Forgejo adapters try the same through their github-like API.
- If a specific self-hosted forge behaves creatively, that is no longer project philosophy. That is local weather.
- Connected storage branch to repo init.
- Connected storage branch to chat creation.
- Connected storage branch to sending messages.
- Connected storage branch to inbox notifications.
- Connected storage branch to read receipts.
- Connected storage branch to members updates.
- Added storage branch to settings export.
- Added storage branch to settings import.
- Added reset default for storage branch.
- Updated the smoke harness for the new reality.
- Verified that remote writes use the storage branch.
- Verified that storage branch is created from `main`.
- Verified that settings export/import does not lose storage branch.
- Verified that reset restores `macaroni`.
- Removed the old behavior where a read-only profile could fill outbox with messages it cannot send anyway.
- Read-only mode now honestly hides the composer.
- Read-only mode now says that a write-capable token is required.
- Unsupported provider no longer pretends writing is possible.
- After adding a token, the composer comes back.
- Updated roadmap.
- Updated development steps.
- Clarified that a full CommonMark engine is not planned.
- Clarified that safe inline markdown is already enough pasta.
- Clarified that notifications are done in the current scope: unread count and embedded sound.
- Did nothing with Browser Notification API.
- Did nothing with permission prompts.
- Did nothing with Kubernetes.

## Almost Invisible Detail Near The Middle

`.macaroni/` can now live in a separate git branch.

Practical shape:

```text
main:
  messenger.html
  README
  docs

macaroni:
  .macaroni/
```

So the source branch no longer has to be the pot where chat data boils.

Code and macaroni can live on different plates now.

## Why It Matters

Before 1.04, a user could open the repo and see:

```text
README.md
messenger.html
.macaroni/
```

It worked.

But it looked like chat walked into the kitchen and sat directly in the documentation.

For new profiles, the default is now:

```text
storageBranch = "macaroni"
```

Old profiles are left alone.

Because backward compatibility is not romance.

It is when a user updates an HTML file and does not lose the chat.

## Read-only Mode

Previously, a read-only profile could try to send a message.

The message went into outbox.

Then the user added a token.

Then outbox tried to come alive.

Technically explainable.

User-facing weird.

Now it is simpler:

```text
no write token -> no composer
```

If the token appears, the composer returns.

No need to queue pasta when the stove has no gas.

## What Did Not Change

- Macaroni Protocol v1 did not change.
- `.macaroni/` layout did not change.
- Encryption 1.01 did not change.
- Plugin boundary did not change.
- GitHub/GitLab/GitVerse/Gitea/Forgejo adapters are still browser-side.
- Optional batch write is still not implemented.
- A complete git client in HTML is still not the goal.
- We still do not pull `isomorphic-git` from npm.
- Backend is still absent.
- `messenger.html` is still one file.

## Result

Version `1.04` looks like a release about a tiny Settings field.

That is intentional.

Tiny field.

Separate branch.

Less dirt in `main`.

Seriously, just a hygiene patch.
