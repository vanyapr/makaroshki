# Macaroni Messenger 1.04

Дата: 2026-06-15

Тип релиза: hygiene patch, официально опять ничего страшного.

Главная идея релиза:

Мелкие правки вокруг настроек, веток и read-only режима.

## Что Поменялось

- Уточнили, что branch называется `macaroni`, а каталог всё ещё `.macaroni/`.

- Разделили source branch и storage branch.

- Сделали так, чтобы старые профили без `storageBranch` не ломались и продолжали читать старую ветку.
- Научили GitHub adapter создавать storage branch от source branch, если её ещё нет.
- Научили GitLab adapter делать то же самое своим способом.
- Научили GitVerse, Gitea и Forgejo adapters пытаться сделать то же самое через свой github-like API.
- Уточнили, что если конкретный self-hosted forge ведёт себя творчески, это уже не философия проекта, а местная погода.
- Подключили storage branch к init repo.

- Подключили storage branch к read receipts.
- Подключили storage branch к members update.
- Добавили storage branch в settings export.
- Добавили storage branch в settings import.
- Добавили reset default для storage branch.
- Обновили smoke harness под новую реальность.
- Проверили, что remote write идёт в storage branch.
- Проверили, что storage branch создаётся от `main`.
- Проверили, что settings export/import не теряет storage branch.
- Проверили, что reset возвращает `macaroni`.
- Убрали старое поведение, где read-only profile мог набивать outbox сообщениями, которые он всё равно не может отправить.
- Read-only режим теперь честно скрывает composer.
- Read-only режим теперь говорит, что нужен token с правом записи.
- Unsupported provider теперь тоже не притворяется, что можно писать.
- После добавления token composer возвращается.
- Обновили roadmap.

- Уточнили, что full CommonMark engine не делаем.

## Почти Незаметная Деталь Ближе К Середине

`.macaroni/` теперь можно хранить в отдельной git branch.

Практический смысл:

```text
main:
  messenger.html
  README
  docs

macaroni:
  .macaroni/
```

То есть source branch больше не обязан быть кастрюлей для переписки.

Теперь можно держать код и макароны в разных тарелках.

## Почему Это Важно

До 1.04 пользователь мог открыть repo и увидеть:

```text
README.md
messenger.html
.macaroni/
```

Это работало.

Но выглядело так, будто чат пришёл на кухню и сел прямо в документацию.

Теперь для новых профилей default другой:

```text
storageBranch = "macaroni"
```

Старые профили не трогаем.

Потому что backward compatibility - это не романтика.

Это когда пользователь обновил HTML-файл и не потерял чат.

## Read-only Режим

Раньше read-only profile мог попытаться отправить сообщение.

Сообщение падало в outbox.

Потом пользователь добавлял token.

Потом outbox пытался ожить.

Это было технически объяснимо.

И пользовательски странно.

Теперь всё проще:

```text
нет write token -> нет composer
```

Если token появился - composer вернулся.

Макароны не надо держать в очереди, если у плиты нет газа.

## Что Не Поменялось

- Macaroni Protocol v1 не поменялся.
- `.macaroni/` layout не поменялся.
- Encryption 1.01 не поменялась.
- Plugin boundary не поменялся.
- GitHub/GitLab/GitVerse/Gitea/Forgejo adapters всё ещё browser-side.
- Optional batch write всё ещё не реализован.
- Полный git client в HTML всё ещё не цель.
- `isomorphic-git` из npm всё ещё не тащим.
- Backend всё ещё отсутствует.
- `messenger.html` всё ещё один файл.
